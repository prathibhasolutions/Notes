Part A — Introduction & Environment Setup

1. What is Selenium, and Why Learn It?

Selenium is a free, open-source tool that controls a real web browser programmatically – it can open pages, click buttons, fill forms, and read page content exactly as a human user would, but automatically and repeatably. It is the industry-standard tool for automating functional testing of web applications.

Job Relevance
  • Selenium WebDriver (what these notes cover) is the core browser-automation API, used with Python, Java, C#, or JavaScript.
  • It is a mandatory, near-universal skill for QA Automation Engineer, SDET (Software Development Engineer in Test), and Test Automation Developer job roles.
  • Real jobs use Selenium to build automated regression suites that run on every code change, catching bugs before they reach users – far faster and more reliable than manual re-testing.

2. Selenium Architecture & Components

"Selenium" is actually a family of tools; understanding how they relate helps make sense of job postings and documentation.

  • Selenium WebDriver – the core library that sends commands directly to a real browser via its native automation driver. This is what "Selenium" means in almost all modern job contexts, and what these notes teach.
  • Selenium Grid – distributes tests to run in parallel across many machines/browsers at once, used for large test suites (see Section 51).
  • Selenium IDE – a browser extension for record-and-playback test creation, mainly used for quick prototyping, not for serious frameworks.
  • WebDriver talks to a browser-specific driver executable (e.g. chromedriver for Chrome, geckodriver for Firefox), which translates commands into real browser actions.

3. Installing Python Packages: selenium & webdriver-manager

Two packages are needed: selenium itself, and webdriver-manager, which automatically downloads and manages the correct browser driver version for you – avoiding the old, error-prone process of manually downloading a matching chromedriver.exe.

  • Run both installs from a terminal/command prompt before writing any code.
  • Selenium 4 (the current major version) uses a completely different, simpler API than older Selenium 3 tutorials you may find online – these notes use Selenium 4 syntax throughout.

5. Your First Selenium Script

This script opens Chrome, loads your local login.html practice page, prints its title, and closes the browser – the smallest possible complete Selenium program.

  • webdriver.Chrome() launches a new, real Chrome browser window controlled by your script.
  • driver.get(url) navigates to a page – local files use a file:// URL.
  • driver.quit() closes the browser and ends the session – always call this when done, ideally in a finally block so the browser closes even if an error occurs.
from selenium import webdriver
from selenium.webdriver.chrome.service import Service
from webdriver_manager.chrome import ChromeDriverManager
import pathlib

# Build a file:// URL that works on any operating system
practice_page = pathlib.Path("practice_site/login.html").resolve().as_uri()

# webdriver-manager downloads/matches the correct chromedriver automatically
service = Service(ChromeDriverManager().install())
driver = webdriver.Chrome(service=service)

try:
    driver.get(practice_page)
    print("Page title is:", driver.title)   # Practice Login Page
finally:
    driver.quit()

6. The WebDriver Object & Browser Options

Beyond just launching a plain browser, an Options object lets you configure how the browser starts – essential for real automation jobs (e.g. running headless on a build server, disabling notification pop-ups that could block clicks).

  • Create a ChromeOptions object, add arguments to it, then pass it into webdriver.Chrome(service=..., options=...).
  • Common arguments: --start-maximized, --disable-notifications, --incognito, --headless=new (see Section 37).
from selenium import webdriver
from selenium.webdriver.chrome.options import Options
from selenium.webdriver.chrome.service import Service
from webdriver_manager.chrome import ChromeDriverManager

options = Options()
options.add_argument("--start-maximized")
options.add_argument("--disable-notifications")

service = Service(ChromeDriverManager().install())
driver = webdriver.Chrome(service=service, options=options)
driver.get("https://example.com")
print(driver.title)
driver.quit()

7. Browser Navigation Commands

These commands control which page the browser is showing, mimicking the browser's own address bar and back/forward buttons.

  • driver.get(url) – loads a URL and waits for the page to finish loading.
  • driver.back() / driver.forward() – navigate browser history, same as clicking the back/forward buttons.
  • driver.refresh() – reloads the current page.
from selenium import webdriver
import pathlib, time

login_page = pathlib.Path("practice_site/login.html").resolve().as_uri()

driver = webdriver.Chrome()
driver.get(login_page)
driver.get("https://example.com")
time.sleep(1)
driver.back()          # returns to login.html
time.sleep(1)
driver.forward()       # goes forward again to example.com
driver.refresh()       # reloads example.com
driver.quit()

8. Browser Information & Window Commands

These commands read information about the current page/browser window, and control the window itself – used constantly for both automation logic and assertions in tests.

  • driver.title – the current page's title (a property, not a method – no parentheses).
  • driver.current_url – the current page's URL.
  • driver.page_source – the full raw HTML of the current page as a string.
  • driver.maximize_window(), driver.minimize_window(), driver.set_window_size(width, height) – control the window size.
  • driver.close() – closes only the current tab/window (the browser process may stay open if other tabs remain).
  • driver.quit() – closes ALL windows/tabs and ends the entire WebDriver session – always use this to properly clean up at the end of a script.
from selenium import webdriver
import pathlib

driver = webdriver.Chrome()
driver.maximize_window()
driver.get(pathlib.Path("practice_site/login.html").resolve().as_uri())

print("Title:", driver.title)              # Practice Login Page
print("URL:", driver.current_url)
print("Page source length:", len(driver.page_source))

driver.quit()

9. Understanding the DOM & Using Browser DevTools

Selenium locates elements within the page's DOM (Document Object Model) – the browser's tree structure of every HTML tag. Before writing a locator, a tester must first find that element's ID, class, or structure using the browser's built-in DevTools – this is a daily, hands-on skill for any automation job.

Daily Job Skill
  • In Chrome, right-click any element on a page and choose "Inspect" (or press F12) to open DevTools and highlight that element's exact HTML.
  • Use Ctrl+F inside the DevTools Elements panel to test a CSS selector or XPath directly in the browser before using it in code – this instantly confirms if a locator is correct and unique.
  • The Console tab lets you run JavaScript directly, e.g. document.querySelectorAll('.form-control').length, useful for quickly checking how many elements match a selector.

Part B — Locators: Finding Elements

10. What is a Locator? The By Class

A locator is the address Selenium uses to find one specific element on a page. Every locator strategy is used through the same By class combined with find_element() or find_elements().

  • Import once: from selenium.webdriver.common.by import By.
  • General pattern: driver.find_element(By.STRATEGY, "value").
  • Choosing the right, most stable locator is one of the most important practical skills in automation – prefer ID, then CSS Selector, then XPath, in that order of preference when available.

11. Locating by ID

The fastest and most reliable locator, since an ID should be unique on the page – always the first choice when available.

from selenium.webdriver.common.by import By

username_field = driver.find_element(By.ID, "username")
username_field.send_keys("testuser")

12. Locating by Name

Uses the HTML name attribute – common on form input fields, especially older or server-rendered websites.

password_field = driver.find_element(By.NAME, "password")
password_field.send_keys("Secret@123")

13. Locating by Class Name

Uses the HTML class attribute. Note: only a single class name is allowed here – if an element has multiple space-separated classes, use a CSS Selector instead (Section 16).

login_btn = driver.find_element(By.CLASS_NAME, "btn")   # NOT "btn btn-primary"
login_btn.click()

14. Locating by Tag Name

Locates by the HTML tag itself (e.g. all <a> or <input> elements) – almost never unique on its own, so it's typically used with find_elements (plural) to get a whole list.

all_inputs = driver.find_elements(By.TAG_NAME, "input")
print("Number of input fields on page:", len(all_inputs))

15. Locating by Link Text & Partial Link Text

Locates an <a> (hyperlink) element by its visible text – only works on links, never other elements.

  • LINK_TEXT – must match the link's full visible text exactly.
  • PARTIAL_LINK_TEXT – matches if the link's text contains the given substring anywhere.
forgot_link = driver.find_element(By.LINK_TEXT, "Forgot password?")
forgot_link.click()

# or, matching just part of the text:
forgot_link = driver.find_element(By.PARTIAL_LINK_TEXT, "Forgot")

16. Locating by CSS Selector

CSS Selectors use the same syntax as CSS stylesheets to target elements – generally faster than XPath and the preferred choice when ID alone is not enough.

  • #id – by ID. .class – by class. tag – by tag name.
  • tag[attribute='value'] – by any attribute, e.g. input[type='password'].
  • parent > child – direct child. parent descendant (space) – any descendant.
  • .class1.class2 (no space) – element having BOTH classes.
driver.find_element(By.CSS_SELECTOR, "#username")
driver.find_element(By.CSS_SELECTOR, ".btn.btn-primary")
driver.find_element(By.CSS_SELECTOR, "input[type='password']")
driver.find_element(By.CSS_SELECTOR, "#login-form > button")

17. Locating by XPath (Absolute & Relative)

XPath navigates the page as a tree using path expressions – the most powerful and flexible locator, able to select elements by text content or by relationship to other elements, which CSS alone cannot always do.

  • Absolute XPath (starts with a single /) – the full path from the document root, e.g. /html/body/form/input[1]. Very fragile – breaks if the page structure changes even slightly. Avoid in real projects.
  • Relative XPath (starts with //) – searches anywhere in the document, e.g. //input[@id='username']. This is what should be used in practice.
  • //tag[@attribute='value'] – by attribute. //tag[text()='exact text'] – by exact visible text.
driver.find_element(By.XPATH, "//input[@id='username']")
driver.find_element(By.XPATH, "//button[text()='Login']")
driver.find_element(By.XPATH, "//label[text()='Password']/following-sibling::input")

18. Dynamic XPath & CSS with Functions

Real applications often have IDs/classes that change dynamically (e.g. id="user-4471") – these functions locate elements using only a stable, partial piece of an attribute.

  • XPath contains() – //input[contains(@id,'user')] matches any ID containing "user".
  • XPath starts-with() – //input[starts-with(@id,'user')] matches IDs beginning with "user".
  • CSS equivalent – [id*='user'] (contains), [id^='user'] (starts with), [id$='field'] (ends with).
driver.find_element(By.XPATH, "//input[contains(@id,'user')]")
driver.find_element(By.CSS_SELECTOR, "input[id*='user']")
driver.find_element(By.CSS_SELECTOR, "input[id^='user']")

19. find_element vs find_elements

The single most important distinction to remember: singular vs plural changes both the return type and the error behaviour.

  • find_element(...) – returns ONE WebElement (the first match). Raises NoSuchElementException if nothing matches.
  • find_elements(...) – returns a Python list of WebElements (possibly empty). Never raises an error if nothing matches – instead returns an empty list, which is a safe way to check "does this element exist?".
checkboxes = driver.find_elements(By.NAME, "hobby")
print("Found", len(checkboxes), "checkboxes")

# Safe existence check pattern (no exception even if missing):
error_messages = driver.find_elements(By.CLASS_NAME, "error")
if len(error_messages) == 0:
    print("No error message displayed - good")

Part C — Interacting with Web Elements

20. Text Boxes (send_keys, clear)

Text input fields are the most common element type on any form – typing into them and clearing them is a foundational skill.

  • element.send_keys("text") – types the given text into the field, character by character, exactly like a real user typing.
  • element.clear() – empties any existing text in the field before typing new text, avoiding accidental concatenation with old values.
username = driver.find_element(By.ID, "username")
username.clear()
username.send_keys("qa_tester")

password = driver.find_element(By.ID, "password")
password.clear()
password.send_keys("Secure@123")

21. Buttons (click)

The .click() method simulates a real mouse click on any clickable element – buttons, links, checkboxes, radio buttons all use the same method.

login_button = driver.find_element(By.ID, "login-btn")
login_button.click()

22. Checkboxes

Checkboxes are also clicked with .click(), but since clicking toggles the state, it is best practice to first check whether it is already selected to avoid accidentally un-checking it.

reading_checkbox = driver.find_element(By.ID, "hobby-reading")
if not reading_checkbox.is_selected():
    reading_checkbox.click()

music_checkbox = driver.find_element(By.ID, "hobby-music")
if not music_checkbox.is_selected():
    music_checkbox.click()

23. Radio Buttons

Radio buttons work the same as checkboxes, but only one in a group (matching name attribute) can be selected at a time – clicking one automatically de-selects the others in that group.

female_radio = driver.find_element(By.ID, "gender-female")
female_radio.click()
print("Female selected:", female_radio.is_selected())   # True
male_radio = driver.find_element(By.ID, "gender-male")
print("Male selected:", male_radio.is_selected())        # False (auto-deselected)

24. Static Dropdowns (Select Class)

A real HTML <select> dropdown is NOT clicked directly – Selenium provides a dedicated Select class with purpose-built methods, which is far more reliable than trying to click options manually.

  • Import: from selenium.webdriver.support.ui import Select, then wrap the element: Select(driver.find_element(...)).
  • select_by_visible_text("India") – selects by the text shown to the user.
  • select_by_value("in") – selects by the option's underlying value attribute.
  • select_by_index(1) – selects by position (0-based).
from selenium.webdriver.support.ui import Select

country_dropdown = Select(driver.find_element(By.ID, "country"))
country_dropdown.select_by_visible_text("India")
# equivalent alternatives:
# country_dropdown.select_by_value("in")
# country_dropdown.select_by_index(1)

selected = country_dropdown.first_selected_option
print("Currently selected:", selected.text)   # India

25. Multi-Select Dropdowns

Some <select multiple> dropdowns allow choosing several options at once – the same Select class handles this, simply by calling a select method more than once.

skills_dropdown = Select(driver.find_element(By.ID, "skills"))
skills_dropdown.select_by_visible_text("Python")
skills_dropdown.select_by_visible_text("Selenium")

all_selected = skills_dropdown.all_selected_options
print([opt.text for opt in all_selected])   # ['Python', 'Selenium']

skills_dropdown.deselect_all()   # clears every selection

26. Links

Links are just <a> elements, clicked the same way as buttons, but their destination URL can also be read without clicking, using get_attribute("href").

link = driver.find_element(By.ID, "forgot-link")
print("Link destination:", link.get_attribute("href"))   # https://example.com/
link.click()

27. Reading Text and Attributes

Beyond just interacting with elements, tests constantly need to read what is displayed, to verify the application behaved correctly.

  • element.text – the visible, rendered text inside an element (a property, no parentheses).
  • element.get_attribute("attribute_name") – reads any HTML attribute's value, e.g. "value", "class", "placeholder", "href".
heading = driver.find_element(By.ID, "page-title")
print(heading.text)   # Login Page

username_field = driver.find_element(By.ID, "username")
print(username_field.get_attribute("placeholder"))   # Enter username
print(username_field.get_attribute("value"))          # current typed value, if any

28. Element State Checks

These methods check the current state of an element, commonly used inside assertions or "if" conditions before deciding what action to take next.

  • is_displayed() – True if the element is visible on the page (not hidden by CSS).
  • is_enabled() – True if the element can be interacted with (not disabled).
  • is_selected() – True if a checkbox/radio/option is currently selected/checked.
message = driver.find_element(By.ID, "message")
print("Message visible:", message.is_displayed())   # False (hidden by CSS initially)

login_btn = driver.find_element(By.ID, "login-btn")
print("Button enabled:", login_btn.is_enabled())     # True

29. Working with Lists of Elements

Real pages often have repeated elements (a list of products, table rows, search results) – find_elements returns them all as a list which can then be looped through with standard Python.

checkboxes = driver.find_elements(By.NAME, "hobby")
for box in checkboxes:
    label_text = box.get_attribute("id")
    print(f"Checkbox '{label_text}' selected: {box.is_selected()}")

# Select all checkboxes on the page in one loop:
for box in checkboxes:
    if not box.is_selected():
        box.click()

Part D — Advanced User Interactions

30. ActionChains – Mouse Hover

Some elements (like dropdown menus) only appear when the mouse hovers over a trigger element – a plain .click() cannot simulate this, so Selenium provides the ActionChains class to build up complex, multi-step mouse/keyboard interactions.

  • Import: from selenium.webdriver.common.action_chains import ActionChains.
  • Build an action, then call .perform() to actually execute it – nothing happens until .perform() is called.
from selenium.webdriver.common.action_chains import ActionChains

heading = driver.find_element(By.ID, "page-title")
actions = ActionChains(driver)
actions.move_to_element(heading).perform()

ActionChains(driver).context_click(heading).perform()

33. Keyboard Actions (Keys Class)

The Keys class provides constants for non-printable keys (Enter, Tab, Escape, Ctrl, arrow keys) so they can be sent through send_keys() just like normal text, either directly on an element or as part of an ActionChains sequence.

from selenium.webdriver.common.keys import Keys

search_box = driver.find_element(By.ID, "username")
search_box.send_keys("qa_tester")
search_box.send_keys(Keys.ENTER)          # press Enter, e.g. to submit a form

search_box.send_keys(Keys.CONTROL, "a")   # select all text
search_box.send_keys(Keys.DELETE)         # then delete it

# Using ActionChains for key combinations:
ActionChains(driver).key_down(Keys.CONTROL).send_keys("a").key_up(Keys.CONTROL).perform()

34. Handling Multiple Windows/Tabs

Clicking a link with target="_blank" opens a new browser tab – but Selenium's focus stays on the ORIGINAL tab until explicitly switched, since a driver session can only "drive" one window at a time.

  • driver.window_handles – a list of unique IDs, one per currently open window/tab.
  • driver.current_window_handle – the ID of the window Selenium is currently focused on.
  • driver.switch_to.window(handle) – switches control to a specific window/tab by its handle.
import pathlib
driver.get(pathlib.Path("practice_site/forms.html").resolve().as_uri())

original_window = driver.current_window_handle
driver.find_element(By.ID, "new-tab-link").click()   # opens login.html in a new tab

# Wait until a second window exists, then switch to it:
for handle in driver.window_handles:
    if handle != original_window:
        driver.switch_to.window(handle)
        break

print("Now on:", driver.title)   # Practice Login Page

driver.close()                          # closes only this new tab
driver.switch_to.window(original_window) # go back to the original tab
print("Back on:", driver.title)         # Practice Forms Page

35. Handling Frames (iframes)

An <iframe> embeds an entirely separate HTML document inside the page. Selenium cannot see elements inside a frame until it explicitly switches its focus into that frame – a very common beginner mistake is a "NoSuchElementException" simply because the code never switched into the frame first.

  • driver.switch_to.frame(locator_or_element_or_index) – switches focus into a frame, by its ID/name, its WebElement, or its numeric index.
  • driver.switch_to.default_content() – switches focus back out to the main page.
driver.get(pathlib.Path("practice_site/forms.html").resolve().as_uri())

driver.switch_to.frame("practice-frame")             # switch into the iframe by its id
frame_text = driver.find_element(By.ID, "frame-text")
print(frame_text.text)                                 # This text is inside an iframe.

driver.switch_to.default_content()                    # switch back to the main page
heading = driver.find_element(By.TAG_NAME, "h1")      # now visible again
print(heading.text)

36. Handling JavaScript Alerts, Confirms & Prompts

A JavaScript alert(), confirm(), or prompt() is a native browser popup, entirely OUTSIDE the page's HTML – it cannot be located with find_element at all. Selenium handles these through a separate switch_to.alert interface.

  • driver.switch_to.alert – gets a handle to the currently open popup.
  • alert.accept() – clicks "OK". alert.dismiss() – clicks "Cancel".
  • alert.text – reads the popup's displayed message.
  • alert.send_keys("text") – types into a prompt() popup's input box before accepting.
driver.get(pathlib.Path("practice_site/forms.html").resolve().as_uri())

driver.find_element(By.ID, "alert-btn").click()
alert = driver.switch_to.alert
print("Alert says:", alert.text)   # This is a simple alert
alert.accept()

driver.find_element(By.ID, "confirm-btn").click()
confirm = driver.switch_to.alert
confirm.dismiss()                  # clicks Cancel

driver.find_element(By.ID, "prompt-btn").click()
prompt = driver.switch_to.alert
prompt.send_keys("QA Tester")
prompt.accept()

37. Headless Browser Execution

"Headless" means running the browser with no visible window at all – it still does everything a normal browser does internally, just without drawing anything on screen. This is essential for running tests on a CI/CD build server (Section 68), which usually has no display/monitor at all, and it also runs noticeably faster.

CI/CD Requirement
  • Add the argument --headless=new (the modern headless mode) to ChromeOptions before creating the driver.
  • Always set an explicit window size in headless mode too, since there's no visible window to "maximize" – some pages render differently at small default sizes.
  • Debug tip: if a headless test fails mysteriously, temporarily remove the headless argument to watch it run visibly, or take a screenshot (Section 46) at the point of failure.
from selenium import webdriver
from selenium.webdriver.chrome.options import Options

options = Options()
options.add_argument("--headless=new")
options.add_argument("--window-size=1920,1080")

driver = webdriver.Chrome(options=options)
driver.get("https://example.com")
print(driver.title)   # works exactly the same, just with no visible window
driver.quit()

38. Why Waits are Needed (The Synchronization Problem)

A real web page often loads data asynchronously (e.g. via JavaScript/AJAX after the initial page load) – an element might not exist in the DOM the instant Selenium's script reaches that line. Without a wait, Selenium tries to find the element too early and throws NoSuchElementException, even though the element would have appeared a fraction of a second later. This "synchronization problem" is one of the most common causes of flaky (unreliable) automated tests in real jobs.

Most Common Interview Topic
  • Never use time.sleep() in real test code – it always waits the full fixed time even if the element appeared instantly (wasting time), and still fails if the page happens to be slower than the fixed value (unreliable). Proper waits solve both problems.
  • Selenium provides three professional wait strategies: Implicit Wait, Explicit Wait, and Fluent Wait.

39. Implicit Wait

A single, global setting applied once per driver session: for every find_element call, Selenium will keep retrying to find the element for up to the given time before giving up and raising an error.

  • Set once, right after creating the driver: driver.implicitly_wait(seconds).
  • Applies automatically and silently to every single locator call for the rest of the session – simple, but less precise/flexible than Explicit Wait.
  • Never mix Implicit and Explicit Waits in the same script – this is a well-documented cause of unpredictable, inconsistent wait times, since the two can interact in confusing ways.
driver = webdriver.Chrome()
driver.implicitly_wait(10)   # applies to every find_element call for this whole session

driver.get(pathlib.Path("practice_site/forms.html").resolve().as_uri())
dynamic_box = driver.find_element(By.ID, "dynamic-box")   # will retry for up to 10s if not found yet

40. Explicit Wait (WebDriverWait + Expected Conditions)

Waits for one SPECIFIC condition to become true, on one specific element, up to a maximum timeout – far more precise and the industry-standard, recommended approach for real automation frameworks.

  • Import: from selenium.webdriver.support.ui import WebDriverWait and from selenium.webdriver.support import expected_conditions as EC.
  • Pattern: WebDriverWait(driver, timeout).until(EC.some_condition(locator)).
  • Polls (checks) every 0.5 seconds by default, and returns as soon as the condition is true – much faster than a fixed sleep when the element appears quickly.
from selenium.webdriver.support.ui import WebDriverWait
from selenium.webdriver.support import expected_conditions as EC

driver.get(pathlib.Path("practice_site/forms.html").resolve().as_uri())

# The #dynamic-box text changes from "Loading..." to "Content Loaded" after 2 seconds -
# wait explicitly for that exact text to appear instead of guessing a fixed sleep time:
wait = WebDriverWait(driver, 10)
wait.until(EC.text_to_be_present_in_element((By.ID, "dynamic-box"), "Content Loaded"))

dynamic_box = driver.find_element(By.ID, "dynamic-box")
print(dynamic_box.text)   # Content Loaded

41. Fluent Wait

A more configurable version of Explicit Wait, letting you control both the polling frequency (how often to re-check) and which exceptions to silently ignore while waiting – useful when an element occasionally throws a temporary "stale element" error while the page is still updating.

from selenium.webdriver.support.ui import WebDriverWait
from selenium.common.exceptions import NoSuchElementException, StaleElementReferenceException

fluent_wait = WebDriverWait(
    driver,
    timeout=10,
    poll_frequency=1,   # check every 1 second instead of the default 0.5
    ignored_exceptions=[NoSuchElementException, StaleElementReferenceException]
)

element = fluent_wait.until(lambda d: d.find_element(By.ID, "dynamic-box"))
print(element.text)

42. Common Expected Conditions Reference

The expected_conditions module (imported as EC) provides many ready-made conditions for the most common waiting scenarios – knowing this list well saves having to write custom wait logic.

  • EC.presence_of_element_located(locator) – element exists in the DOM (may still be invisible).
  • EC.visibility_of_element_located(locator) – element exists AND is visible on screen.
  • EC.element_to_be_clickable(locator) – element is visible AND enabled (safe to click).
  • EC.invisibility_of_element_located(locator) – waits for an element (e.g. a loading spinner) to disappear.
  • EC.text_to_be_present_in_element(locator, text) – waits for specific text to appear inside an element.
  • EC.alert_is_present() – waits for a JavaScript alert/confirm/prompt to appear.
  • EC.title_contains(text) / EC.url_contains(text) – waits for the page title/URL to change.
  • EC.number_of_windows_to_be(n) – waits until exactly n windows/tabs are open (useful before switching, see Section 34).
login_btn = WebDriverWait(driver, 10).until(
    EC.element_to_be_clickable((By.ID, "login-btn"))
)
login_btn.click()

43. Handling Web Tables

Data tables are extremely common in real applications (reports, admin panels, search results). There is no special "Table" class in Selenium – instead, rows and cells are located with normal XPath/CSS and looped through with Python.

driver.get(pathlib.Path("practice_site/forms.html").resolve().as_uri())

rows = driver.find_elements(By.CSS_SELECTOR, "#data-table tbody tr")
print("Number of rows:", len(rows))

for row in rows:
    cells = row.find_elements(By.TAG_NAME, "td")
    name, role, city = [c.text for c in cells]
    print(f"{name} | {role} | {city}")

# Find a specific row by its text content, then read a value from it, using XPath:
ravi_role = driver.find_element(
    By.XPATH, "//table[@id='data-table']//td[text()='Ravi']/following-sibling::td[1]"
)
print("Ravi's role:", ravi_role.text)   # Developer

44. File Upload

Uploading a file in Selenium does NOT require clicking to open the operating system's file browser dialog (which Selenium cannot see or control) – instead, simply send_keys() the full absolute file path directly to the hidden <input type="file"> element.

  • This trick works because the browser accepts a typed path into a file input exactly as if the OS dialog had returned it.
  • Always use an absolute path (e.g. built with pathlib), not a relative one, since the browser process's working directory may differ from the script's.
import pathlib

# Create a small sample file to upload, for practice:
sample_file = pathlib.Path("sample_upload.txt")
sample_file.write_text("This is a test file for Selenium upload practice.")

driver.get(pathlib.Path("practice_site/forms.html").resolve().as_uri())
upload_input = driver.find_element(By.ID, "file-upload")
upload_input.send_keys(str(sample_file.resolve()))   # no click() needed at all

45. Handling File Downloads

Selenium cannot see the browser's native "Save As" dialog either – the standard, reliable approach is to pre-configure Chrome (via Options) to automatically save all downloads to a known folder with no prompt, then simply check that folder with normal Python file operations afterward.

import os, time, pathlib
from selenium.webdriver.chrome.options import Options

download_dir = str(pathlib.Path("downloads").resolve())
os.makedirs(download_dir, exist_ok=True)

options = Options()
options.add_experimental_option("prefs", {
    "download.default_directory": download_dir,
    "download.prompt_for_download": False,
})

driver = webdriver.Chrome(options=options)
driver.get(pathlib.Path("practice_site/advanced.html").resolve().as_uri())
driver.find_element(By.ID, "download-link").click()

time.sleep(2)   # brief pause for the (very small) file to finish saving
downloaded_files = os.listdir(download_dir)
print("Downloaded files:", downloaded_files)   # ['sample.txt']
assert "sample.txt" in downloaded_files

46. Taking Screenshots

Capturing a screenshot is one of the most valuable debugging tools in test automation – especially automatically capturing one the moment a test fails, so a human can see exactly what the page looked like (this is built as a PyTest fixture in Section 58).

  • driver.save_screenshot("path.png") – captures the full visible browser window.
  • element.screenshot("path.png") – captures just one specific element.
driver.get(pathlib.Path("practice_site/login.html").resolve().as_uri())
driver.save_screenshot("full_page.png")

heading = driver.find_element(By.ID, "page-title")
heading.screenshot("heading_only.png")

47. Handling Cookies

Cookies store small pieces of data (like login session tokens) in the browser. Selenium can read, add, and delete them – commonly used to skip a slow UI login by injecting a valid session cookie directly.

  • driver.get_cookies() – returns a list of all cookies for the current domain.
  • driver.add_cookie({"name": "...", "value": "..."}) – adds a cookie (the browser must already be on that domain first).
  • driver.delete_all_cookies() – clears every cookie, useful for resetting state between tests.
driver.get("https://example.com")
print(driver.get_cookies())

driver.add_cookie({"name": "session_id", "value": "abc123"})
driver.delete_all_cookies()

48. JavaScript Executor

For the rare cases Selenium's normal API cannot handle directly (scrolling precisely, clicking an element blocked by an overlay, reading a JS variable), execute_script() runs raw JavaScript directly inside the browser.

  • driver.execute_script("javascript code", optional_arguments...).
  • Pass a WebElement as an argument and reference it as arguments[0] inside the script.
  • Use sparingly – it bypasses Selenium's normal waiting/interactability checks, which can hide real bugs in the tested application.
login_btn = driver.find_element(By.ID, "login-btn")

# Click via JS - a common workaround when a normal .click() is blocked by an overlay:
driver.execute_script("arguments[0].click();", login_btn)

# Read a value directly from the page's JavaScript:
title_via_js = driver.execute_script("return document.title;")
print(title_via_js)

# Set a field's value directly via JS (bypasses real typing - use only when necessary):
username = driver.find_element(By.ID, "username")
driver.execute_script("arguments[0].value = 'forced_value';", username)

49. Scrolling the Page

Some elements must be scrolled into view before Selenium can reliably click them (an element completely off-screen may not be considered "interactable"). The JavaScript Executor is the standard way to scroll precisely.

driver.get(pathlib.Path("practice_site/advanced.html").resolve().as_uri())

# Scroll a specific element into view:
target = driver.find_element(By.ID, "scroll-target")
driver.execute_script("arguments[0].scrollIntoView(true);", target)

# Scroll to the absolute bottom of the page:
driver.execute_script("window.scrollTo(0, document.body.scrollHeight);")

# Scroll by a specific pixel offset:
driver.execute_script("window.scrollBy(0, 500);")

50. Handling Calendars / Date Pickers

Date pickers vary hugely between websites – some are a simple native HTML5 <input type="date"> (which just accepts typed text), while others are complex custom JavaScript pop-up calendars requiring clicking through months/days one at a time.

  • Native date input – simply send_keys() the date, usually in MM/DD/YYYY format for the US locale Chrome typically uses.
  • Custom JS calendar widgets – typically require: click to open the calendar, then use relative XPath (e.g. //td[text()='15']) to click the specific day, sometimes clicking "next month" arrows in a loop first if the target month isn't shown yet.
driver.get(pathlib.Path("practice_site/advanced.html").resolve().as_uri())

dob_field = driver.find_element(By.ID, "dob")
dob_field.send_keys("08/15/2025")   # MM/DD/YYYY for a native date input

Part G — Grid, Custom Widgets & Robustness

51. Selenium Grid Basics

Selenium Grid lets test scripts run on remote machines instead of the local computer, and lets many tests run in parallel across multiple browsers/machines at once – essential for keeping a large test suite's total run time reasonable in a real company pipeline.

Scaling Test Suites
  • A Grid has one Hub (the central coordinator that receives test requests) and one or more Nodes (machines that actually run a browser and execute the test).
  • In code, instead of webdriver.Chrome(), connect to the Hub's URL using webdriver.Remote(), specifying which browser/OS is needed – the Hub then assigns an available matching Node to run it.
  • Modern teams often run Grid using Docker containers (one container per Node) for easy, disposable setup – a common real-world CI pattern.
from selenium import webdriver
from selenium.webdriver.chrome.options import Options

options = Options()
driver = webdriver.Remote(
    command_executor="http://localhost:4444/wd/hub",   # the Grid Hub's address
    options=options
)
driver.get("https://example.com")
driver.quit()

52. Handling Dynamic (Custom) Dropdowns

Not every "dropdown" on a real website is a genuine HTML <select> element – many are custom-built with <div>s and JavaScript for a fancier look (as seen in many modern UI component libraries). The Select class (Section 24) does NOT work on these – instead, treat it as a simple click-to-open, click-to-choose sequence like any other elements.

driver.get(pathlib.Path("practice_site/advanced.html").resolve().as_uri())

driver.find_element(By.ID, "custom-dropdown-toggle").click()   # opens the custom list

banana_option = WebDriverWait(driver, 5).until(
    EC.element_to_be_clickable((By.XPATH, "//div[@data-value='banana']"))
)
banana_option.click()

result = driver.find_element(By.ID, "custom-dropdown-result")
print(result.text)   # Selected: banana

53. Common Selenium Exceptions

Recognising these specific exceptions immediately tells an experienced automation engineer what actually went wrong, without needing to debug from scratch – a frequent, practical interview topic.

  • NoSuchElementException – the locator matched nothing; usually a wrong locator or the element genuinely not loaded yet (missing wait).
  • ElementNotInteractableException – the element exists but cannot currently be interacted with (e.g. hidden, or covered by another element).
  • ElementClickInterceptedException – another element (often a popup/overlay) is visually on top of the target, blocking the click.
  • StaleElementReferenceException – the element was found, but the page then changed/reloaded that part of the DOM, so the old reference is no longer valid; re-locate the element and try again.
  • TimeoutException – an Explicit Wait's condition never became true within its timeout.
  • NoAlertPresentException – tried switch_to.alert when no popup was actually open.
from selenium.common.exceptions import (
    NoSuchElementException, TimeoutException, StaleElementReferenceException
)

54. Robust Waiting Patterns & Try-Except in Automation

Combining Explicit Waits with targeted try-except blocks makes scripts resilient to the timing issues that cause most "flaky" (inconsistently failing) test suites in real jobs.

from selenium.common.exceptions import TimeoutException, StaleElementReferenceException

def click_with_retry(driver, locator, attempts=3):
    """Retries a click if the element goes stale between locating and clicking."""
    for attempt in range(attempts):
        try:
            element = WebDriverWait(driver, 10).until(EC.element_to_be_clickable(locator))
            element.click()
            return
        except StaleElementReferenceException:
            continue   # element changed underneath us - just try again
    raise TimeoutException(f"Could not click {locator} after {attempts} attempts")

click_with_retry(driver, (By.ID, "login-btn"))

55. Best Practices for Robust, Stable Scripts

  • Prefer ID > CSS Selector > XPath, in that order, whenever a stable option exists.
  • Always use Explicit Waits with specific conditions instead of time.sleep().
  • Never mix Implicit and Explicit Waits in the same script.
  • Always call driver.quit() in a finally block (or a PyTest fixture teardown, Section 58) so the browser closes even if the test fails partway through.
  • Keep locators and page logic separate from test logic using the Page Object Model (Part I).
  • Avoid hard-coded test data inside scripts – use Parameterized tests (Section 59) or external data files instead.
  • Take a screenshot automatically on failure (Section 58) – it saves enormous debugging time later.

56. Introduction to PyTest

Selenium only controls the browser – it has no concept of "tests", "pass/fail", or generating reports. PyTest is Python's most widely used testing framework, and combining it with Selenium is the standard, expected setup for a professional automation job.

Framework
  • Install: pip install pytest.
  • Any function whose name starts with test_, inside a file whose name starts with test_, is automatically discovered and run as a test.
  • Run all tests in a folder simply by typing pytest in the terminal.
--- File: test_sample.py ---
def test_addition():
    assert 2 + 2 == 4

def test_string_upper():
    assert "hello".upper() == "HELLO"
pytest test_sample.py -v
# -v (verbose) shows each test's name and PASSED/FAILED status individually

57. Assertions in PyTest

PyTest uses Python's plain built-in assert keyword – no special assertion methods to memorise. If the condition is False, PyTest automatically shows a detailed, readable failure message comparing the actual vs expected values.

def test_page_title():
    # ... (Selenium setup and driver.get(...) here)
    assert driver.title == "Practice Login Page"

def test_login_button_visible():
    login_btn = driver.find_element(By.ID, "login-btn")

58. PyTest Fixtures (Setup/Teardown)

A Fixture is a reusable function that prepares something a test needs (like opening the browser) before the test runs, and cleans it up (like closing the browser) afterward – avoiding copy-pasting the same setup code into every single test function.

  • Decorate a function with @pytest.fixture; any test function that takes it as a parameter automatically receives its returned value.
  • Code before yield runs as setup; code after yield runs as teardown, even if the test fails or raises an error.
  • Fixtures are usually placed in a special file named conftest.py so they are automatically shared across every test file in the project, with no explicit import needed.
--- File: conftest.py ---
import pytest
from selenium import webdriver

@pytest.fixture
def driver():
    drv = webdriver.Chrome()
    drv.maximize_window()
    yield drv                 # <-- the test runs at this point, using this driver
    drv.quit()                # <-- runs after the test finishes, pass or fail

--- File: test_login.py ---
import pathlib
from selenium.webdriver.common.by import By

def test_page_title(driver):        # pytest automatically supplies the 'driver' fixture
    driver.get(pathlib.Path("practice_site/login.html").resolve().as_uri())
    assert driver.title == "Practice Login Page"

A more advanced version that automatically takes a screenshot only when a test fails, using PyTest's built-in hook system:

--- File: conftest.py (extended) ---
import pytest
from selenium import webdriver

@pytest.hookimpl(tryfirst=True, hookwrapper=True)
def pytest_runtest_makereport(item, call):
    outcome = yield
    report = outcome.get_result()
    setattr(item, f"result_{report.when}", report)

@pytest.fixture
def driver(request):
    drv = webdriver.Chrome()
    drv.maximize_window()
    yield drv
    failed = getattr(request.node, "result_call", None)
    if failed is not None and failed.failed:
        drv.save_screenshot(f"failure_{request.node.name}.png")
    drv.quit()

Data-driven testing runs the exact same test logic multiple times against different input data – e.g. testing a login form with five different username/password combinations, without writing five separate test functions.

Part I — Framework Design: Page Object Model

63. What is the Page Object Model (POM)?

POM is the industry-standard design pattern for structuring a real automation project: every web page (or major component) gets its own Python class, containing that page's locators and the actions a user can perform on it. Test files then only call these actions, never touching raw locators directly. This is asked about in nearly every automation job interview.

Standard Interview Topic
  • Without POM – every test file repeats the same locators; if the application's HTML changes, every test file must be updated individually.
  • With POM – locators live in exactly one place (the page class); if the HTML changes, only that one class needs updating, and every test automatically benefits.
  • Makes tests dramatically more readable: login_page.enter_username("bob") instead of driver.find_element(By.ID, "username").send_keys("bob").

64. Building a Page Object Class

A Page Object class typically stores the driver in its constructor, defines locators as class-level constants, and exposes one method per user action.

--- File: pages/login_page.py ---
from selenium.webdriver.common.by import By
from selenium.webdriver.support.ui import WebDriverWait
from selenium.webdriver.support import expected_conditions as EC

class LoginPage:
    # Locators - defined once, in exactly one place
    USERNAME_FIELD = (By.ID, "username")
    PASSWORD_FIELD = (By.ID, "password")
    LOGIN_BUTTON = (By.ID, "login-btn")
    PAGE_HEADING = (By.ID, "page-title")

    def __init__(self, driver):
        self.driver = driver
        self.wait = WebDriverWait(driver, 10)

    def enter_username(self, username):
        self.driver.find_element(*self.USERNAME_FIELD).send_keys(username)

    def enter_password(self, password):
        self.driver.find_element(*self.PASSWORD_FIELD).send_keys(password)

    def click_login(self):
        self.wait.until(EC.element_to_be_clickable(self.LOGIN_BUTTON)).click()

    def login(self, username, password):
        """A higher-level action combining the three steps above."""
        self.enter_username(username)
        self.enter_password(password)
        self.click_login()

    def get_heading_text(self):
        return self.driver.find_element(*self.PAGE_HEADING).text

67. Cross-Browser Testing

A real application must work correctly on multiple browsers (Chrome, Firefox, Edge). Rather than hard-coding webdriver.Chrome() everywhere, a professional framework makes the browser choice a configurable parameter.

from selenium import webdriver

def get_driver(browser_name="chrome"):
    if browser_name == "chrome":
        return webdriver.Chrome()
    elif browser_name == "firefox":
        return webdriver.Firefox()
